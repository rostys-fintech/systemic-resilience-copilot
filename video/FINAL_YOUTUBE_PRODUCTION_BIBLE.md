# Systemic Resilience Copilot — Final YouTube Production Bible

**Purpose:** final judge-facing product film for Devpost / YouTube  
**Target runtime:** 2:15–2:25  
**Format:** 1920×1080, 30 fps, 16:9  
**Primary theme for capture:** Light theme  
**Narration authority:** `video/VOICEOVER_MASTER.md`

---

# 1. CREATIVE DIRECTION

The film must feel like a **premium fintech product film**, not a screen recording, not a pitch deck, and not a research presentation.

The judge should understand the product even if they never read the README.

## One-sentence film idea

**A backup can exist and still fail; the Copilot shows the first recovery condition that actually fails, the next justified action, and where evidence stops.**

## Emotional tone

- calm authority;
- serious institutional software;
- no hype;
- no fear language;
- no “AI magic”;
- confidence comes from traceability, not spectacle.

## Visual language

- use the live product UI as the hero asset;
- warm light theme for readability and consistency with Devpost media;
- dark navy hero and darker decision moments for contrast;
- clean 3–6% digital zooms;
- slow cursor movement;
- sparse one-line overlays;
- short cuts only when they help comprehension;
- no stock footage;
- no talking head;
- no code, terminal, repository browsing, research tables, equations, or manuscripts.

---

# 2. JUDGE JOURNEY

The film follows one causal chain only:

**Problem → Apertus extraction → Rules → Decision → Apertus explanation → Narrow fix → Next UNKNOWN → Systemic lens → Close**

Canonical proof path:

**95 min > 60 min → S5 RED / B2 → REPAIR_EXECUTION → 45 min → S6 UNKNOWN → S7 UNKNOWN**

The viewer must leave with six clear ideas:

1. backup existence is not executable recovery;
2. Apertus structures language into evidence;
3. deterministic rules control the decision;
4. `UNKNOWN` is preserved instead of guessed away;
5. fixing one problem reveals the next justified question;
6. systemic shared exposure is not automatically a capacity shortage.

# 4. EXACT OVERLAY SYSTEM

Use no more than five major overlays in the film:

1. **Backup exists ≠ executable recovery**
2. **Apertus structures the evidence**
3. **95 min > 60 min → S5 RED · B2**
4. **AI explains. Rules decide.**
5. **95 → 45 → next state becomes UNKNOWN**
6. **Shared recovery resource ≠ proven shortage**

If six feels visually heavy, remove overlay #2 first.

## Overlay design

- 1 line only;
- 42–52 px at 1080p;
- semibold/bold, not extra-black;
- maximum width about 60% of frame;
- use dark navy translucent plate over light UI;
- use warm bone plate over dark hero;
- 10–14 frame fade/slide in;
- 10 frame fade out;
- no bouncing, glitching, typewriter effects, neon glow or kinetic typography.

---

# 5. CAMERA / SCREEN MOTION

This is a screen-based product film, so motion must be editorial, not decorative.

Use only:
- 3–6% slow digital push;
- gentle pan to the current proof area;
- cursor hover before each important click;
- clean cut between product states;
- optional 6–8 frame dissolve only between hero and closing frame.

Do not:
- zoom beyond 108% digital crop unless the source is 4K;
- whip-pan;
- rapidly scroll;
- circle the cursor;
- show browser chrome unnecessarily;
- switch Light / Dark theme during the film.

---

Record seven independent raw clips, each with 2 seconds of extra handle:

1. `01_HERO_PRODUCT.mov/mp4`

## Browser pre-flight

- 1920×1080 capture minimum;
- browser zoom 100%;
- Light theme locked;
- unrelated tabs closed;
- bookmarks bar hidden;
- desktop notifications disabled;
- no autofill popups;
- no tokens, settings pages or private GitHub visible;
- production root loaded fresh;
- run one rehearsal before recording finals;
- if a live Apertus call fails, discard only that clip and rerecord it.

# 7. VOICE DIRECTION

Use the exact script in `video/VOICEOVER_MASTER.md`.

Voice characteristics:
- male;
- age impression ~25–40;
- neutral/international English;
- confident and conversational;
- medium-low pitch;
- no dramatic trailer cadence;
- no exaggerated excitement;
- clear separation of `S five`, `B two`, `S six`, `S seven`.

Audio first. Edit visuals to the locked voice — never narrate while clicking the site.

---

# 8. CAPTIONS

Burn in English captions because Devpost judges may watch embedded video muted.

Style:
- 1–2 lines maximum;
- sentence case;
- 34–42 px at 1080p;
- semibold;
- off-white text;
- subtle dark translucent background or 2–3 px shadow/outline;
- bottom-safe margin 80–105 px;
- never cover the active metric / decision card;
- split technical terms so `S5 RED · B2` stays on one line when possible.

Do not color every keyword. At most one emphasized term per caption.

---

# 9. SOUND DESIGN

Music is optional. Silence + clean voice is better than generic corporate music.

If music is used:
- minimal ambient electronic / modern institutional texture;
- no melody that competes with voice;
- around -30 to -32 LUFS below narration;
- lower another 4–6 dB during the `95 > 60` decision;
- no cinematic riser or bass drop;
- fade music out during the final sentence.

Optional UI SFX:
- one very soft click on the four key actions only;
- no beeps for every animation step;
- no whoosh transitions.

---

# 10. EDITING ORDER

1. Place final voice track on timeline.
2. Add the seven trimmed product clips.
3. Match visual proof to the exact spoken sentence.
4. Remove waiting/dead time from live calls while preserving beginning + final result.
5. Add the five/six overlays.
6. Add gentle 3–6% push-ins.
7. Add captions.
8. Mix voice + optional ambient bed.
9. Run claim audit.
10. Export master.
11. Watch once with sound.
12. Watch again muted.

If the muted version is confusing, the visual edit is not finished.

# 11. YOUTUBE PACKAGING

## Final title

**A Backup Exists. Will It Recover in Time? | Systemic Resilience Copilot**

This is stronger than a generic project-name-only title because it starts with the actual product problem while remaining professional.

## Thumbnail concept

Use a real high-resolution product frame, not AI art.

Composition:
- dark navy hero background;
- large `95 min > 60 min` proof on the right;
- short text on left: **WILL IT RECOVER IN TIME?**
- small Systemic Resilience Copilot mark;
- no more than 5–6 words beyond the metric;
- no faces;
- no arrows/circles spam;
- no generic robot/AI imagery;
- no clickbait expressions.

## Visibility

**Unlisted** is appropriate for Devpost unless the hackathon explicitly requires Public.

## Description structure

First two lines must explain the product before links:

`Systemic Resilience Copilot turns natural-language recovery evidence into a traceable next action. Apertus structures and explains; deterministic rules preserve the decision state and UNKNOWN evidence.`

Then include:
- canonical proof path;
- live demo;
- GitHub;
- technical report;
- public-safe / synthetic scenario disclosure;
- statement that the walkthrough is edited product footage, not a continuous live recording.

# 12. EXPORT SETTINGS

- MP4 / H.264 High Profile;
- 1920×1080;
- 30 fps;
- AAC 48 kHz;
- 12–18 Mbps VBR target;
- keyframe every ~2 seconds;
- web optimized / fast start;
- no watermark;
- full-range UI text must remain sharp after YouTube compression.

If possible, export a 1440p or 4K upscaled YouTube master **only if** the source screen capture is truly high enough quality; do not fake sharpness from a low-resolution screen recording.

---

# 13. FINAL CLAIM AUDIT

The film must not imply:
- predicted bank failure probability;
- realised systemic B3 shortage;
- shared provider = shared failure;
- provider diversity = recoverability;
- public evidence = confidential supervisory evidence;
- Apertus makes the final supervisory decision;
- synthetic demo cases are measured incidence.

Keep the architecture truthful:

**Apertus structures / challenges / explains. Deterministic rules decide.**

---

# 14. RELEASE GATE

The film is ready only if a judge can answer all six questions after one viewing:

1. What problem does this solve?
2. What does Apertus actually do?
3. What do the rules actually do?
4. Why is `UNKNOWN` useful?
5. What changes after the fix?
6. What makes the systemic lens different from a generic provider-concentration dashboard?

If any answer is unclear, fix the edit before YouTube upload.

## Final standard

**Short, visual, product-first, evidence-disciplined, and memorable.**
